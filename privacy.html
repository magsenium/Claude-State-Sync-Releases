Claude State Sync — a Visual Studio Code extension

Claude State Sync copies Claude Code's state between your own computers using your own Google Drive or Microsoft OneDrive account. There is no server in the middle. The developer of this extension operates no backend, receives no copy of your files, and cannot read the data you sync.

In one line: your files travel from your computer to your own cloud storage and back. Nothing is sent anywhere else, and nothing is collected.

What the extension reads on your computer

Only what you switch on. Each of these is a separate toggle in the extension's settings, and each maps to a location Claude Code already uses on your machine:

  • CLAUDE.md, plans, skills, agents, commands and settings from ~/.claude
  • Per-project memory files
  • Claude Code session transcripts (the record of your conversations)

Session transcripts can contain anything you typed into Claude Code, including code and file paths. They are treated as your private data throughout: they are compressed and uploaded to your own cloud storage, and nowhere else.

Where the data goes

Provider Location Permission requested
Google Drive A folder in your Drive, named ClaudeStateSync by default drive.file
Microsoft OneDrive This app's own folder in your OneDrive Files.ReadWrite.AppFolder, User.Read
A git repository A repository you name, reached with the git already on your computer None — no account, no token held by the extension

These are the narrowest permissions the providers offer for this purpose. drive.file grants access only to files this application itself creates — the extension cannot see, list or read any other file in your Google Drive. Files.ReadWrite.AppFolder confines the extension to a single application folder in OneDrive. User.Read is used solely to display which account you are signed in as, in the extension's own panel.

One OneDrive exception, and only if you choose it. Microsoft has moved some personal accounts to a storage backend where the app folder is refused outright, leaving those accounts unable to sync at all. For them the extension offers to keep the store in an ordinary ClaudeStateSync folder instead, which requires Files.ReadWrite — a permission that can read and write your whole OneDrive. It is never selected for you: the default is the app-folder permission above, the swap is explained before it happens, needs a fresh sign-in, and can be reversed in the extension's settings. Even then, nothing leaves your account: the extension still only writes its own folder, and no server of ours is involved.

What the developer collects

Nothing. Specifically:

  • No analytics, telemetry, crash reporting or usage statistics.
  • No account names, email addresses, file names or file contents are transmitted to the developer.
  • No server is operated by the developer; the extension talks directly to Google or Microsoft from your computer.
  • The extension's diagnostic log stays on your machine, in the Output panel of your editor.

Sign-in and tokens

Signing in uses the provider's standard OAuth flow in your browser. The resulting access and refresh tokens are stored in Visual Studio Code's encrypted secret storage on that computer and are never written to a synced file, a log, or any location the developer can reach.

Google API Services — Limited Use

Claude State Sync's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. Data obtained through Google APIs is used only to provide the syncing feature you asked for; it is not transferred to any third party, is not used for advertising, and is not read by humans.

Your control

  • Choose what is synced — every category has its own toggle, and individual sessions can be excluded.
  • Delete the storage folder from your Drive or OneDrive at any time; the extension will simply find nothing there.
  • Revoke access at any time: Google account permissions or Microsoft account permissions.
  • Uninstall the extension; nothing of yours is left behind on any server, because none was used.
